# 🎵📥 Telegram-бот: музыка + медиа по ссылке

Готовый бот на Python, который делает ровно то, что на скриншотах:

1. **Поиск музыки** — пишешь `девочка с дайвинчика`, бот показывает список треков с длительностью и кнопками, по нажатию присылает mp3 с обложкой и тегами. Источники: Hitmo и Zvyki (готовые файлы), резерв — SoundCloud.
2. **Медиа по ссылке** — кидаешь ссылку на TikTok / Twitter-X / Instagram / Vimeo / Reddit / SoundCloud, бот скачивает и присылает видеофайл в чат. Ссылки YouTube не поддерживаются: с серверных IP он требует вход (подробности в разделе ограничений).
3. **Работает в любом чате** — набери `@имя_бота <ссылка>` без добавления бота в чат (inline-режим).

Всё на бесплатных компонентах, без платных API и подписок.

Ключевой момент: **не нужен ни один платный API**. Музыка берётся с Hitmo и Zvyki (готовые mp3/AAC по прямым ссылкам), остальное — через yt-dlp. Никаких ключей, регистраций и лимитов, кроме лимита самого Telegram.

## Быстрый старт на Windows

### 1. Создать бота и получить токен
В Telegram: **@BotFather** → `/newbot` → имя → username → скопировать токен вида `123456789:AA...`.

### 2. Установить Python и ffmpeg
- Python 3.11+ с [python.org](https://www.python.org/downloads/) — при установке обязательно галочка **Add Python to PATH**.
- ffmpeg (нужен для mp3 и склейки видео):
  ```powershell
  winget install Gyan.FFmpeg
  ```
  После установки **перезапусти терминал** и проверь: `ffmpeg -version`.

### 3. Запустить бота
Двойной клик по **`start.bat`** — он сам создаст виртуальное окружение, поставит зависимости, создаст `.env` и откроет его в блокноте.

Вставь токен в строку `BOT_TOKEN=...`, сохрани, запусти `start.bat` ещё раз. Готово.

<details>

```powershell
cd tg-media-bot
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
notepad .env          # вставить BOT_TOKEN

```
</details>

### 4. Проверить
В Telegram: `/start` → отправь `кино - группа крови` → должен появиться список треков. Потом отправь ссылку на TikTok — бот напишет «⬇️ Скачиваю…» и **превратит это же сообщение** в видео (или в текст ошибки, если не вышло).

## Inline-режим: вызов в любом чате (как у @coboldbot)

Бота **не нужно добавлять в чат**. Достаточно в любом диалоге набрать:

```
@имя_твоего_бота https://www.tiktok.com/@user/video/123456
@имя_твоего_бота кино группа крови
```

Дальше бот показывает список вариантов («📷 Фото-видео», «🎵 Только звук» или список треков). После выбора появляется сообщение «⬇️ Скачиваю…», и **это же сообщение превращается** в видео, картинку, mp3 или в короткую ошибку — как у cobold. Тип файла определяется сам: фото-пост станет картинкой, ролик — видео.

**Включение (один раз, только через @BotFather):**
1. `/setinline` → выбрать бота → подсказка, например `🔗 Ссылка или название трека`.
2. `/setinlinefeedback` → выбрать бота → **100%**. Без этого бот не узнает, что результат выбрали, и «скачиваю…» останется висеть навсегда.

**Как это работает.** Inline-бот обязан ответить мгновенно, поэтому сначала он отправляет обычный текстовый результат, а потом редактирует его по `inline_message_id` — уже с настоящим файлом (`editMessageMedia`). Кэш `file_id` в `cache.db` дополнительно позволяет отдавать ранее скачанное совсем без ожидания.

## Если не подключается к Telegram

В России `api.telegram.org` часто заблокирован — бот упадёт с ошибкой «Не могу подключиться к api.telegram.org».

Варианты:
- включить VPN в режиме **TUN** (весь трафик системы, не только браузер) — тогда ничего настраивать не нужно;
- указать SOCKS5-прокси от VPN в `.env`:
  ```env
  TELEGRAM_PROXY=socks5://127.0.0.1:1080
  ```
- либо держать бота на зарубежном сервере (Oracle и т.п.) — там блокировки нет.

`PROXY` (для yt-dlp) и `TELEGRAM_PROXY` задаются отдельно: YouTube может быть доступен напрямую, а Telegram — нет, и наоборот.

## Настройки `.env`

| Переменная | Обязательно | Что делает |
|---|---|---|
| `BOT_TOKEN` | да | токен от @BotFather |
| `COOKIES_FILE` | нет | путь к `cookies.txt` — спасает от «подтвердите, что вы не робот» и открывает Instagram |
| `TELEGRAM_PROXY` | нет | прокси для Bot API, `socks5://127.0.0.1:1080` (если Telegram заблокирован) |
| `PROXY` | нет | прокси для yt-dlp: `socks5://127.0.0.1:1080` или `http://user:pass@host:port` |
| `MAX_UPLOAD_MB` | нет | лимит файла, по умолчанию 49 (максимум Bot API — 50) |

## Хостинг 24/7 (компьютер можно выключать)

Бот должен жить на сервере: только тогда он работает, когда твой ПК выключен, и заодно не упирается в блокировки и медленный VPN.

### Oracle Cloud Always Free — бесплатно навсегда

Бессрочно бесплатный сервер (ARM: до 4 ядра / 24 ГБ RAM). Для регистрации нужна банковская карта — она проверяется, но на Always Free ничего не списывается.

**1. Создать аккаунт и инстанс**
1. https://www.oracle.com/cloud/free/ → регистрация (регион лучше европейский: Frankfurt / Amsterdam).
2. Меню → **Compute → Instances → Create instance**.
3. Image: **Canonical Ubuntu 24.04**. Shape: **Ampere → VM.Standard.A1.Flex**, 1 OCPU / 6 ГБ RAM (можно больше — в лимит Always Free влезает до 4/24).
   Если ARM-мощности нет («out of capacity») — бери **VM.Standard.E2.1.Micro** (1 ГБ RAM), этого тоже хватает.
4. В разделе **Add SSH keys** выбери *Generate a key pair for me* и **скачай приватный ключ** (`.key`) — он нужен для входа.
5. Create. Через минуту появятся **Public IP address** и имя пользователя `ubuntu`.

**2. Открыть порт для SSH** (обычно уже открыт)
Networking → VCN → Security Lists → Default → Add Ingress Rule: source `0.0.0.0/0`, protocol TCP, port `22`.

**3. Загрузить проект с Windows** (PowerShell в папке проекта):

```powershell
powershell -ExecutionPolicy Bypass -File deploy\upload.ps1 -Server <IP> -Key C:\путь\к\ssh-key.key
```

Скрипт упакует проект (без `.venv`, логов и кэша) и положит его в `~/tg-media-bot` на сервере.

**4. Установить на сервере**

```bash
ssh -i C:\путь\к\ssh-key.key ubuntu@<IP>
sudo bash ~/tg-media-bot/deploy/deploy.sh
nano ~/tg-media-bot/.env          # вставить BOT_TOKEN, сохранить (Ctrl+O, Enter, Ctrl+X)
sudo bash ~/tg-media-bot/deploy/deploy.sh
```

Скрипт сам поставит Python, ffmpeg, создаст venv, добавит swap (нужен для склейки видео на слабом инстансе), пропишет и запустит systemd-сервис. Повторный запуск = обновление кода.

**5. Проверить**

```bash
systemctl status tg-media-bot      # active (running)
journalctl -u tg-media-bot -f      # живые логи
```

Всё, бот работает на сервере: ПК можно выключать. VPN на сервере не нужен — Telegram там доступен напрямую (поэтому `TELEGRAM_PROXY` и `PROXY` в `.env` остаются пустыми).

**Обновление кода** — снова залить папку `upload.ps1` и запустить `sudo bash ~/tg-media-bot/deploy/deploy.sh`. yt-dlp обновляется сам каждую ночь таймером `yt-dlp-update.timer`.

### Если Oracle не подошёл

- **Render (бесплатно, без карты)** — пошаговая инструкция в `DEPLOY-RENDER.md`: код в GitHub → Web Service из `Dockerfile` → вебхук ставится автоматически, плюс бесплатный пингер, чтобы контейнер не засыпал.
- **Любой дешёвый VPS** (Hetzner CX22 ~€4, Aeza, Timeweb Cloud, Racknerd) — те же команды, только загрузить файлы через `scp`.
- **Docker** на любом сервере:
  ```bash
  cp .env.example .env   # вписать токен
  docker compose up -d --build
  docker compose logs -f
  ```
- **Свой ПК / Raspberry Pi** — работает, но только пока компьютер включён.

> У бесплатных PaaS (Render, Koyeb, Bot-Hosting) мало памяти и CPU, а контейнер засыпает без трафика. Музыка (Hitmo и Zvyki отдают готовые файлы) там работает нормально, тяжёлое видео с ffmpeg — медленно. Для постоянной нагрузки лучше VPS.

### Вебхук вместо long polling

Если хостинг даёт публичный HTTPS-адрес (Render, Koyeb, Bot-Hosting), достаточно задать `PUBLIC_URL` (на Render подставляется сам из `RENDER_EXTERNAL_URL`) — бот поднимет HTTP-сервер на `PORT`, поставит вебхук и будет отвечать `200 ok` на `/health`. Без `PUBLIC_URL` бот работает через long polling, как на VPS.

## Ограничения и как их обходить

### 1. Лимит 50 МБ
Обычный Bot API не даёт ботам отправлять файлы больше 50 МБ. В коде есть авто-понижение качества (1080 → 720 → 480 → 360), пока файл не влезет.
Кардинальное решение — свой **локальный Bot API server** (`telegram-bot-api --local`), тогда лимит 2 ГБ, но это отдельный сервис и больше возни.

### 2. YouTube не поддерживается
С серверного IP (Render, VPS, облака) YouTube требует вход и отдаёт
«Sign in to confirm you're not a bot». Cookies, смена клиентов и PO-токен это
не обходят: датацентровые адреса YouTube блокирует на уровне IP. Поэтому YouTube
убран из бота совсем — и из поиска, и из скачивания по ссылке. На такие ссылки бот
отвечает подсказкой.

Музыку это не задевает: Hitmo и Zvyki отдают готовые файлы напрямую, без обходов.

Если YouTube всё-таки нужен — бота надо ставить на IP, который YouTube не считает
ботом (домашний ПК, реже — VPS в стране без замедления), либо терпеть cookies,
PO-токены и нестабильность.

### 3. Instagram, приватный TikTok, X с ограничениями
Нужны cookies авторизованного аккаунта (`COOKIES_FILE`). Учти риск блокировки аккаунта — используй «пустышку».

### 4. Ссылки на посты Telegram (`t.me/...`)
Их нельзя скачать через Bot API: бот не видит медиа закрытых каналов. Нужен **юзербот** (Telethon/Pyrogram) — вход в твой личный аккаунт по номеру телефона. Это рабочий, но рискованный путь (правила Telegram), поэтому в текущей версии бот вежливо отказывает. Если надо — делается отдельным сервисом.

### 5. Spotify / Apple Music / Yandex Music
yt-dlp их не качает (DRM). Бот распознаёт ссылку и вытаскивает «исполнитель — название», после чего запускает обычный поиск музыки:
- **Spotify** — OG-теги страницы трека (Spotify отдаёт их только «ботовым» User-Agent);
- **Apple Music** — бесплатный iTunes Search API (работает и для ссылок на альбом);
- **Яндекс.Музыка** — публичный API `api.music.yandex.net` без токена (трек или альбом).

Ссылки на альбомы Spotify разобрать нельзя: страницу альбома Spotify отдаёт ботам как заглушку, поэтому бот попросит ссылку на конкретный трек.

## Как это работает внутри

**Музыка.** Сначала Hitmo: разбираем HTML поиска, берём прямые ссылки на mp3. Если результатов мало — параллельно Zvyki (там файл отдаётся то mp3, то AAC: формат определяется по первым байтам, AAC упаковывается в m4a без перекодирования) и SoundCloud через yt-dlp. Название, автор и длительность складываются в кнопки по 8 штук на страницу; по нажатию бот скачивает файл и отправляет его как `audio`.

**Медиа.** Для ссылки сначала делается проход без скачивания: узнать форматы и размеры. По размеру выбирается максимальное качество, влезающее в лимит. Затем скачивается, видео и звук склеиваются в mp4. Бот отправляет сообщение «⬇️ Скачиваю…» и **редактирует его в готовое видео** (`editMessageMedia`); если Telegram не разрешил редактирование — отправляет файл новым сообщением, а статус удаляет. Ошибка так же появляется в том же сообщении. Каждый успешный файл запоминается по `file_id` для inline-режима.

**Безопасность.** Каждый запрос качает в свою временную папку, которая удаляется в `finally` — даже если что-то упало. Старые папки подчищаются при старте. Параллельных скачиваний не больше трёх.
