# 🎵📥 Telegram-бот: музыка + медиа по ссылке

Готовый бот на Python, который делает ровно то, что на скриншотах:

1. **Поиск музыки** — пишешь `девочка с дайвинчика`, бот показывает список треков с длительностью и кнопками, по нажатию присылает mp3 с обложкой и тегами. Источники: Hitmo и Zvyki (готовые файлы), резерв — SoundCloud.
2. **Медиа по ссылке** — кидаешь ссылку на YouTube / TikTok / VK / Twitter-X / Instagram / Vimeo / Reddit / SoundCloud / FurAffinity, бот скачивает и присылает видео, фото или файл в чат. Для VK работают ссылки на видео, клипы, фото и посты на стене (если в посте есть фото — придёт фото). YouTube качается напрямую через yt-dlp с cookies из `COOKIES_FILE`, а при `COBALT_YOUTUBE=1` — через cobalt (подробности в разделе ограничений).
3. **Работает в любом чате** — набери `@имя_бота <ссылка>` без добавления бота в чат (inline-режим).

Всё на бесплатных компонентах, без платных API и подписок.

## Быстрый старт на Windows

### 1. Создать бота и получить токен
В Telegram: **@BotFather** → `/newbot` → имя → username → скопировать токен вида `123456789:AA...`.

### 2. Установить Python и ffmpeg
- Python 3.11+ с [python.org](https://www.python.org/downloads/) — при установке обязательно галочка **Add Python to PATH**.
- ffmpeg (нужен для mp3 и склейки видео):
  ```powershell
  winget install Gyan.FFmpeg
  ```
  После установки **перезапусти терминал** и проверь: `ffmpeg -version`.

### 3. Запустить бота
Двойной клик по **`start.bat`** — он сам создаст виртуальное окружение, поставит зависимости, создаст `.env` и откроет его в блокноте.

Вставь токен в строку `BOT_TOKEN=...`, сохрани, запусти `start.bat` ещё раз. Готово.

<details>
<summary>То же самое вручную</summary>

```powershell
cd tg-media-bot
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
notepad .env          # вставить BOT_TOKEN
python bot.py
```
</details>

### 4. Проверить
В Telegram: `/start` → отправь `кино - группа крови` → должен появиться список треков. Потом отправь ссылку на TikTok — бот напишет «⬇️ Скачиваю…» и **превратит это же сообщение** в видео (или в текст ошибки, если не вышло).

## Inline-режим: вызов в любом чате (как у @coboldbot)

Бота **не нужно добавлять в чат**. Достаточно в любом диалоге набрать:

```
@имя_твоего_бота https://www.tiktok.com/@user/video/123456
@имя_твоего_бота кино группа крови
```

Дальше бот показывает список вариантов («📷 Фото-видео», «🎵 Только звук» или список треков). После выбора появляется сообщение «⬇️ Скачиваю…», и **это же сообщение превращается** в видео, картинку, mp3 или в короткую ошибку — как у cobold. Тип файла определяется сам: фото-пост станет картинкой, ролик — видео.

**Включение (один раз, только через @BotFather):**
1. `/setinline` → выбрать бота → подсказка, например `🔗 Ссылка или название трека`.
2. `/setinlinefeedback` → выбрать бота → **100%**. Без этого бот не узнает, что результат выбрали, и «скачиваю…» останется висеть навсегда.

**Как это работает.** Inline-бот обязан ответить мгновенно, поэтому сначала он отправляет обычный текстовый результат, а потом редактирует его по `inline_message_id` — уже с настоящим файлом (`editMessageMedia`). Кэш `file_id` в `cache.db` дополнительно позволяет отдавать ранее скачанное совсем без ожидания.

## Если не подключается к Telegram

В России `api.telegram.org` часто заблокирован — бот упадёт с ошибкой «Не могу подключиться к api.telegram.org».

Варианты:
- включить VPN в режиме **TUN** (весь трафик системы, не только браузер) — тогда ничего настраивать не нужно;
- указать SOCKS5-прокси от VPN в `.env`:
  ```env
  TELEGRAM_PROXY=socks5://127.0.0.1:1080
  ```
- либо держать бота на зарубежном сервере (Oracle и т.п.) — там блокировки нет.

`PROXY` (для yt-dlp) и `TELEGRAM_PROXY` задаются отдельно: YouTube может быть доступен напрямую, а Telegram — нет, и наоборот.

## Настройки `.env`

| Переменная | Обязательно | Что делает |
|---|---|---|
| `BOT_TOKEN` | да | токен от @BotFather |
| `COOKIES_FILE` | нет | путь к `cookies.txt` — спасает от «подтвердите, что вы не робот» и открывает Instagram |
| `YT_COOKIES` | нет | содержимое `cookies.txt` строкой (для PaaS без диска) |
| `YT_PLAYER_CLIENT` | нет | клиент(ы) YouTube через запятую; обычно не нужен — бот сам перебирает и запоминает рабочий, список показывает `/yt_debug` |
| `COBALT_API` | нет | адрес(а) cobalt для Instagram/Reddit/Rutube (и YouTube при `COBALT_YOUTUBE=1`): `https://host` или `https://host\|Api-Key …`, несколько через запятую |
| `COBALT_YOUTUBE` | нет | `1` — гнать YouTube через cobalt; по умолчанию `0` (yt-dlp + cookies из `COOKIES_FILE`) |
| `COBALT_QUALITY` | нет | стартовое качество видео через cobalt, по умолчанию `1080` |
| `COBALT_SERVICES` | нет | какие сервисы отдавать в cobalt: по умолчанию `instagram,reddit,rutube` (YouTube — отдельный `COBALT_YOUTUBE`) |
| `COBALT_PROXY` | нет | прокси только для запросов в cobalt |
| `POT_SERVER` | нет | адрес локального провайдера PO-токенов (bgutil) для yt-dlp |
| `TELEGRAM_PROXY` | нет | прокси для Bot API, `socks5://127.0.0.1:1080` (если Telegram заблокирован) |
| `PROXY` | нет | прокси для yt-dlp: `socks5://127.0.0.1:1080` или `http://user:pass@host:port` |
| `MAX_UPLOAD_MB` | нет | лимит файла, по умолчанию 49 (максимум Bot API — 50) |

## Хостинг 24/7 (компьютер можно выключать)

Бот должен жить на сервере: только тогда он работает, когда твой ПК выключен, и заодно не упирается в блокировки и медленный VPN.

### Oracle Cloud Always Free — бесплатно навсегда

Бессрочно бесплатный сервер (ARM: до 4 ядра / 24 ГБ RAM). Для регистрации нужна банковская карта — она проверяется, но на Always Free ничего не списывается.

**1. Создать аккаунт и инстанс**
1. https://www.oracle.com/cloud/free/ → регистрация (регион лучше европейский: Frankfurt / Amsterdam).
2. Меню → **Compute → Instances → Create instance**.
3. Image: **Canonical Ubuntu 24.04**. Shape: **Ampere → VM.Standard.A1.Flex**, 1 OCPU / 6 ГБ RAM (можно больше — в лимит Always Free влезает до 4/24).
   Если ARM-мощности нет («out of capacity») — бери **VM.Standard.E2.1.Micro** (1 ГБ RAM), этого тоже хватает.
4. В разделе **Add SSH keys** выбери *Generate a key pair for me* и **скачай приватный ключ** (`.key`) — он нужен для входа.
5. Create. Через минуту появятся **Public IP address** и имя пользователя `ubuntu`.

**2. Открыть порт для SSH** (обычно уже открыт)
Networking → VCN → Security Lists → Default → Add Ingress Rule: source `0.0.0.0/0`, protocol TCP, port `22`.

**3. Загрузить проект с Windows** (PowerShell в папке проекта):

```powershell
powershell -ExecutionPolicy Bypass -File deploy\upload.ps1 -Server <IP> -Key C:\путь\к\ssh-key.key
```

Скрипт упакует проект (без `.venv`, логов и кэша) и положит его в `~/tg-media-bot` на сервере.

**4. Установить на сервере**

```bash
ssh -i C:\путь\к\ssh-key.key ubuntu@<IP>
sudo bash ~/tg-media-bot/deploy/deploy.sh
nano ~/tg-media-bot/.env          # вставить BOT_TOKEN, сохранить (Ctrl+O, Enter, Ctrl+X)
sudo bash ~/tg-media-bot/deploy/deploy.sh
```

Скрипт сам поставит Python, ffmpeg, создаст venv, добавит swap (нужен для склейки видео на слабом инстансе), пропишет и запустит systemd-сервис. Повторный запуск = обновление кода.

**5. Проверить**

```bash
systemctl status tg-media-bot      # active (running)
journalctl -u tg-media-bot -f      # живые логи
```

Всё, бот работает на сервере: ПК можно выключать. VPN на сервере не нужен — Telegram там доступен напрямую (поэтому `TELEGRAM_PROXY` и `PROXY` в `.env` остаются пустыми).

**Обновление кода** — снова залить папку `upload.ps1` и запустить `sudo bash ~/tg-media-bot/deploy/deploy.sh`. yt-dlp обновляется сам каждую ночь таймером `yt-dlp-update.timer`.

### Если Oracle не подошёл

- **Render (бесплатно, без карты)** — пошаговая инструкция в `DEPLOY-RENDER.md`: код в GitHub → Web Service из `Dockerfile` → вебхук ставится автоматически, плюс бесплатный пингер, чтобы контейнер не засыпал.
- **Любой дешёвый VPS** (Hetzner CX22 ~€4, Aeza, Timeweb Cloud, Racknerd) — те же команды, только загрузить файлы через `scp`.
- **Docker** на любом сервере:
  ```bash
  cp .env.example .env   # вписать токен
  docker compose up -d --build
  docker compose logs -f
  ```
- **Свой ПК / Raspberry Pi** — работает, но только пока компьютер включён.

> У бесплатных PaaS (Render, Koyeb, Bot-Hosting) мало памяти и CPU, а контейнер засыпает без трафика. Музыка (Hitmo и Zvyki отдают готовые файлы) там работает нормально, тяжёлое видео с ffmpeg — медленно. Для постоянной нагрузки лучше VPS.

### Вебхук вместо long polling

Если хостинг даёт публичный HTTPS-адрес (Render, Koyeb, Bot-Hosting), достаточно задать `PUBLIC_URL` (на Render подставляется сам из `RENDER_EXTERNAL_URL`) — бот поднимет HTTP-сервер на `PORT`, поставит вебхук и будет отвечать `200 ok` на `/health`. Без `PUBLIC_URL` бот работает через long polling, как на VPS.

## Ограничения и как их обходить

### 1. Лимит 50 МБ
Обычный Bot API не даёт ботам отправлять файлы больше 50 МБ. В коде есть авто-понижение качества (1080 → 720 → 480 → 360), пока файл не влезет.
Кардинальное решение — свой **локальный Bot API server** (`telegram-bot-api --local`), тогда лимит 2 ГБ, но это отдельный сервис и больше возни.

### 2. YouTube, Instagram, Reddit, Rutube: cobalt или yt-dlp
YouTube по умолчанию качается напрямую через **yt-dlp** с cookies из
`COOKIES_FILE` — это быстрее, чем пробовать cobalt, и не зависит от того,
умеет ли конкретный инстанс YouTube. Вернуть YouTube в cobalt можно
переменной `COBALT_YOUTUBE=1`.

Для Instagram/Reddit/Rutube бот сначала пробует **cobalt** (если задан
`COBALT_API`) — это тот же способ, что у [cobold](https://github.com/tskau/cobold):
ссылка уходит в API, обратно приходит готовый файл. Инстансы перечисляются
через запятую или с новой строки; после `|` можно указать ключ
(`Api-Key …` или `Bearer …`). Какие сервисы отдавать в cobalt, задаёт
`COBALT_SERVICES` (по умолчанию `instagram,reddit,rutube`).

Если cobalt не настроен или не справился, работает **yt-dlp**: формат выбирается
с предпочтением h264 + m4a, качество автоматически понижается (1080 → 720 → 480 → 360),
а скачивание обрывается, как только превысило лимит Telegram.

**Честно о публичных инстансах.** Официальный `api.cobalt.tools` YouTube **не поддерживает**,
а бесплатные публичные инстансы требуют токен turnstile (`error.api.auth.jwt.missing`).
Instagram и Reddit на публичных инстансах тоже часто отвечают «нужен вход/приватный пост».
Рабочий вариант — свой cobalt на VPS/домашнем сервере или ключ от владельца инстанса.
Свой cobalt поднимается по [инструкции](https://github.com/imputnet/cobalt/blob/main/docs/run-an-instance.md);
для YouTube ему нужен `YOUTUBE_SESSION_SERVER` (PO-токены) или cookies аккаунта,
для Instagram/Reddit — cookies этих сервисов в инстансе.

Если cobalt не настроен, yt-dlp всё равно попробует скачать напрямую — результат
зависит от IP и текущих клиентов. При блокировке бот подскажет обновить cookies
(`COOKIES_FILE` / `YT_COOKIES`) или включить `COBALT_YOUTUBE=1` с рабочим
`COBALT_API`.

**Если YouTube пишет «Failed to extract any player response».** Это значит, что
YouTube не отдал плеер ни одному клиенту: обычно виноват датацентровый IP Render
или неполные cookies. Бот сам перебирает клиентов (`web_embedded`, `visionos`,
`android_vr`, `mweb` и другие) и запоминает рабочий. Команда
`/yt_debug https://youtu.be/...` показывает, какие клиенты отвечают с вашего
сервера, и заодно проверяет cookies. Если не работает ни один — нужен прокси,
свежие cookies или свой cobalt с PO-токенами.

**Как получить cookies YouTube.** Не копируйте значения вручную: экспорт из
Cookie-Editor часто теряет HttpOnly-пары (`SID`, `HSID`, `APISID`), и с таким
файлом YouTube отвечает хуже, чем вообще без cookies. Надёжнее собрать файл
через yt-dlp из браузера, где вы вошли в YouTube (браузер лучше закрыть):

```bash
python -m yt_dlp --cookies-from-browser chrome --cookies cookies.txt \
  --skip-download "https://www.youtube.com/watch?v=dQw4w9WgXcQ"
```

`chrome` можно заменить на `edge`, `firefox`, `brave`, `opera`, `vivaldi`.
Полученный `cookies.txt` загрузите на Render как **Secret File** с именем
`cookies.txt` и укажите `COOKIES_FILE=/etc/secrets/cookies.txt`. Переменную
`YT_COOKIES` при этом уберите: многострочная вставка часто ломает табы.

Проверка состава (значения не печатаются):

```bash
python inspect_cookies.py cookies.txt
```

Должны быть `SID`, `HSID`, `SSID`, `APISID`, `SAPISID`, `LOGIN_INFO`
и `__Secure-1PSID`/`__Secure-3PSID`.

**Нужен JS-движок.** Свежих cookies мало: YouTube шифрует ссылки на файлы
(n-challenge), и yt-dlp должен решать эту задачу на JavaScript. В Docker-образе
уже стоит Deno и пакет `yt-dlp-ejs`, поэтому на Render всё работает из коробки.
Если запускаете локально — поставьте их и себе, иначе с cookies будет
«Requested format is not available», а без cookies форматов меньше:

```bash
pip install yt-dlp-ejs
# Deno: https://deno.com/ или winget install DenoLand.Deno
```

Проверить, что движок виден, можно командой `/yt_debug <ссылка>` — в отчёте
будет строка `JS-движок: deno 2.x ...; скрипт n-challenge (yt-dlp-ejs): есть 0.8.0`.

Там же есть строка `вход по cookies: …`. Если написано `НЕТ`, файл бесполезен:
YouTube отправляет такой запрос на страницу входа. Для Render это критично —
датацентровый IP без живого входа получает «Sign in to confirm you're not a bot»
на всех клиентах.

Музыку это не задевает: Hitmo и Zvyki отдают готовые файлы напрямую, без обходов.

### 3. Instagram, приватный TikTok, X с ограничениями
Instagram первым делом идёт в cobalt: тогда cookies нужны не боту, а инстансу.
Без cobalt или при его ошибке включается yt-dlp, которому нужны cookies авторизованного
аккаунта (`COOKIES_FILE`). Учти риск блокировки аккаунта — используй «пустышку».

### 4. Ссылки на посты Telegram (`t.me/...`)
Их нельзя скачать через Bot API: бот не видит медиа закрытых каналов. Нужен **юзербот** (Telethon/Pyrogram) — вход в твой личный аккаунт по номеру телефона. Это рабочий, но рискованный путь (правила Telegram), поэтому в текущей версии бот вежливо отказывает. Если надо — делается отдельным сервисом.

### 5. Spotify / Apple Music / Yandex Music
yt-dlp их не качает (DRM). Бот распознаёт ссылку и вытаскивает «исполнитель — название», после чего запускает обычный поиск музыки:
- **Spotify** — OG-теги страницы трека (Spotify отдаёт их только «ботовым» User-Agent);
- **Apple Music** — бесплатный iTunes Search API (работает и для ссылок на альбом);
- **Яндекс.Музыка** — публичный API `api.music.yandex.net` без токена (трек или альбом). Если с серверного IP API отвечает 403/таймаутом (бывает на Render), бот пробует зеркала `api.music.yandex.com`/`.ru`, «ботовые» User-Agent (`TelegramBot`, `facebookexternalhit`) и OG-теги страницы трека (`og:title` + `og:description` вида «Исполнитель • Трек • 2024»), а в самом конце — страницу через прокси Google-переводчика (`music-yandex-ru.translate.goog`), серверы которого Яндекс не блокирует. Причина отказа пишется в лог и в сообщение об ошибке.

Ссылки на альбомы Spotify разобрать нельзя: страницу альбома Spotify отдаёт ботам как заглушку, поэтому бот попросит ссылку на конкретный трек.

### 6. FurAffinity и Cloudflare
`www.furaffinity.net` целиком стоит за Cloudflare, поэтому бот идёт к странице работы несколькими путями: обычный браузерный User-Agent, «ботовый» `TelegramBot`, прокси Google-переводчика (`www-furaffinity-net.translate.goog`), прокси Microsoft (`translatetheweb.com`), веб-архив и сторонний API FAExport.

**Работы 18+.** Без входа FA отдаёт страницу без картинки: в `og:image` лежит логотип сайта, а `#submissionImg` в HTML просто нет — именно из-за этого раньше вместо работы приходил логотип. Вход по паролю с датацентрового IP FA режет (`503` на POST `/login/`), поэтому основной путь — готовые cookies сессии `a` и `b` из браузера: они уже встроены в `config.py` и переопределяются переменной `FA_COOKIE` (`a=…; b=…`). Если cookies протухли, бот честно попросит их обновить и не будет дёргать вход. Когда `FA_COOKIE` не задан, бот пытается войти сам (`FA_LOGIN`/`FA_PASSWORD`), держит cookies сессии в памяти процесса и повторяет запрос уже под аккаунтом; вход запрашивается только когда картинки нет и не чаще раза в 10 минут.

**Почему не приходит логотип.** Картинки работ лежат на `d.`/`t.furaffinity.net`, а логотип и оформление — на `www.`/`static.`. Бот принимает только «арт-хосты» и отбрасывает `/themes/`, `/img/`, `/css/`, `/js/`, поэтому заглушка уйти вместо работы не может.

Если Cloudflare не пустил вообще (бывает на датацентровых IP), бот присылает сообщение с объяснением, а когда ссылка на файл известна — превью подтягивает сам Telegram: его краулер FurAffinity пускает. Прямые ссылки на файлы (`d.furaffinity.net/…jpg`) тоже принимаются.

**Диагностика.** Если работа 18+ всё равно не приходит, отправьте боту `/fa_debug <ссылка>` — он покажет, что именно отдаёт FA: есть ли `#submissionImg`, что лежит в `og:image`, какие маркеры 18+ на странице, нашлась ли форма входа, какие поля в ней и чем закончился POST (включая код и тело ошибки), а также cookies сессии и наличие cookie `a`. Пароль в отчёте не печатается.

**Если FA отвечает на POST ошибкой 503.** FurAffinity режет вход не только по паролю: с датацентровых IP он может отвечать `503 Service Unavailable` на сам POST `/login/`, хотя страницы работ отдаёт нормально. Признак — в отчёте `/fa_debug` строка `Вход: НЕТ — POST … HTTPError: HTTP Error 503`. Тогда автоматический вход не пройдёт, и остаётся cookies-вариант: войдите в FA в браузере, откройте DevTools → Application → Cookies → `https://www.furaffinity.net` и скопируйте значения cookies `a` и `b`. В Render добавьте переменную `FA_COOKIE=a=…; b=…` (порядок и пробелы не важны). После перезапуска `/fa_debug` должен показать `Cookie a (признак входа): есть`, и работы 18+ начнут скачиваться файлом.

## Как это работает внутри

**Музыка.** Сначала Hitmo: разбираем HTML поиска, берём прямые ссылки на mp3. Дальше параллельно Zvyki (там файл отдаётся то mp3, то AAC: формат определяется по первым байтам, AAC упаковывается в m4a без перекодирования) и SoundCloud через yt-dlp. Запрос вида `фотографирую закат - fem.love` читается как «автор — название» в любом порядке: тире заменяется пробелом для поиска, а при ранжировании проверяются оба варианта. Оригиналы поднимаются выше каверов и ремиксов. Название, автор и длительность складываются в кнопки по 8 штук на страницу (до 5 страниц); по нажатию бот скачивает файл и отправляет его как `audio`.

**Медиа.** Для ссылки сначала делается проход без скачивания: узнать форматы и размеры. По размеру выбирается максимальное качество, влезающее в лимит. Затем скачивается, видео и звук склеиваются в mp4. Бот отправляет сообщение «⬇️ Скачиваю…» и **редактирует его в готовое видео** (`editMessageMedia`); если Telegram не разрешил редактирование — отправляет файл новым сообщением, а статус удаляет. Ошибка так же появляется в том же сообщении. Каждый успешный файл запоминается по `file_id` для inline-режима.

**cobalt (YouTube, Instagram, Reddit, Rutube).** Если задан `COBALT_API`, ссылка сначала уходит в cobalt (POST `/`): бот понимает ответы `tunnel`, `redirect`, `picker` (берёт видео, а если его нет — картинку) и `local-processing`, качает файл по выданному адресу, а ключ отправляет в заголовке `Authorization`. Инстансы перебираются по очереди; если файл больше лимита, качество понижается. YouTube идёт в cobalt всегда, остальные сервисы — из списка `COBALT_SERVICES`. Если cobalt не настроен или ответил ошибкой — работает обычный yt-dlp: в приоритете h264 + m4a, а прогресс-хук обрывает скачивание на лимите и запускает следующую попытку с меньшим качеством.

**VK.** Домен `vk.ru` приводится к `vk.com` (yt-dlp понимает посты на стене только там), короткие `vk.cc`/`vk.link` раскрываются. Если yt-dlp ссылку не разобрал (фото-страницы и посты он не умеет) или в посте нет аудио, бот запрашивает страницу с User-Agent `TelegramBot` — VK отдаёт такому «боту предпросмотра» готовые `og:image`/`og:video` — и качает вложение напрямую. Поэтому работают `vk.ru/photo-…` и `vk.ru/wall-…` с фото в посте; для видео из поста берётся `og:video` (в т.ч. `video_ext.php`). Случайный `video-…` со страницы больше не подхватывается: раньше из-за этого вместо фото мог прийти чужой ролик из рекомендаций. Заглушка VK «Пост из ленты ВКонтакте» (1920×1010, отдаётся постам без вложения) отсеивается по URL и по отсутствию `og:url`.

**FurAffinity.** `www.furaffinity.net` стоит за Cloudflare и с серверного IP отвечает JS-челленджем «Just a moment…», поэтому бот перебирает несколько путей к странице `/view/<id>`: обычный браузерный User-Agent, «ботовый» `TelegramBot`, прокси Google-переводчика (`www-furaffinity-net.translate.goog`), прокси Microsoft-переводчика (`translatetheweb.com`), веб-архив и сторонний API FAExport.

Работы 18+ FA отдаёт только после входа: без сессии `#submissionImg` в HTML нет, а `og:image` — логотип сайта. Поэтому бот логинится сам (`FA_LOGIN`/`FA_PASSWORD`), хранит cookies сессии в одном общем `OpenerDirector` на процесс и повторяет запрос уже под аккаунтом; если сессия протухла — входит заново. Вход нужен только когда картинки нет и не чаще раза в 10 минут, чтобы не злить FA. Из HTML берётся `data-fullview-src` у `#submissionImg` (оригинал), затем `og:image` — но **только с арт-хостов** (`d.`/`t.furaffinity.net`), иначе вместо работы прилетал бы логотип с `www.furaffinity.net/themes/…`. Превью с `t.furaffinity.net` используется лишь если оригинала нет. Файл с CDN качается с браузерными заголовками, `Referer` и cookies — без них CDN отвечает 403. Если Cloudflare не пустил вообще, но ссылка на файл известна, бот просит **Telegram** показать превью по ней (краулер Telegram FurAffinity пускает).

**Безопасность.** Каждый запрос качает в свою временную папку, которая удаляется в `finally` — даже если что-то упало. Старые папки подчищаются при старте. Параллельных скачиваний не больше трёх.
